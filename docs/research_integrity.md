# Research Integrity Checks

ResearchGuard AI enforces strict data hygiene and methodology protocols to ensure the scientific validity of the Phase 5 experiment. This document details the integrity checks implemented to prevent data leakage and experimental bias.

## Leakage Prevention Architecture

Data leakage occurs when information from the validation set influences the training of the model, leading to artificially inflated performance metrics. ResearchGuard AI prevents this through several programmatic barriers:

1. **Connected-Component Grouping**:
   - The SciFact dataset forms a bipartite graph of Claims and Documents. To prevent leakage, a Disjoint Set Union (Union-Find) algorithm maps this graph into strict connected components.
   - During cross-validation, these components act as grouping IDs, ensuring that no claim or document appears in both the training and validation splits of a given fold.

2. **Zero-Overlap Assertions**:
   - The `experiment_runner.py` executes explicit, programmatic assertions before every fold to guarantee zero leakage of:
     - Group IDs
     - Document IDs
     - Claim IDs
     - Claim textual content
     - Rationale textual content
     - Exact instance tuples

## Transformation Integrity

All feature transformations and scaling are strictly confined to the training distribution:

1. **Train-Only TF-IDF Fitting**: The `TfidfVectorizer` is instantiated and `fit()` exclusively on the text of the training fold. Validation folds are processed using only `transform()`.
2. **Train-Only Scaler Fitting**: The `StandardScaler` for the Logistic Regression model is `fit()` exclusively on the extracted features of the training fold.
3. **Train-Only Cosine Threshold Selection**: The optimal cosine similarity threshold for the baseline model is calculated by maximizing the F1 score exclusively on the training fold. It is never tuned on validation data.

## Model Independence

1. **BGE Embeddings**: The `BAAI/bge-small-en-v1.5` embedding model is utilized purely as an off-the-shelf feature extractor. It is never retrained or fine-tuned during the experiment, preventing embedding-layer memorization.
2. **Runtime Classifier Independence**: The Phase 6 runtime pipeline loads the serialized Phase 5 ML artifact (`logistic_regression_scifact.joblib`) for inference only. It does not perform automated retraining or continuous learning.

## Evaluation Integrity

1. **Identical Validation Instances**: Both the Cosine Threshold baseline and the Logistic Regression model are evaluated against the exact same validation instances in every fold, ensuring an apples-to-apples comparison.
2. **Missing Evidence Handling**: Missing evidence is handled neutrally by the pipeline; it is not artificially mapped to CONTRADICT to inflate baseline metrics.
3. **Metrics Representation**: Documentation explicitly isolates SciFact metrics from runtime PDF accuracy to prevent misleading claims about the system's production capability.
4. **Result Preservation**: The results generated by the Phase 5 experiment are immutably stored in `data/experiments/phase5_scifact_experiment_results.json` and are treated as the single authoritative source of truth for all documentation.
